# AirPulse：Codex 状态与键盘联动

项目已由 Keyphore Windows 更名为 AirPulse。应用名称、图标与前端/Rust 项目名称使用新名称；插件标识、接收器名称和本地数据路径保留旧值，以兼容已安装插件与已有配置，详见 [README](../README.md#数据与兼容性)。本次更名不更改 Hook 定义或自动重装现有插件。

本阶段实现主线是 Codex 生命周期 Hook → 本地状态文件 → Tauri 全局聚合 → Air75 V3 所选灯区。原始目标见 `superpowers/specs/2026-10-08-keyphore-windows-design.md`；当前以用户最新的五种状态、自定义颜色和三种展示区域要求为准。现有桌面应用及 Hook 接收器已编译，插件已安装启用并由用户信任；侧灯、主键区的真实执行与完成状态已实机确认。一键安装入口及安装包资源配置已实现源码，尚未重新编译或实测；托盘和开机启动界面仍属后续范围。

## 状态与操作

| 全局状态 | 默认颜色 | 判定规则 |
| --- | --- | --- |
| 工具失败 | 红色 `#FF3B30` | 任一跟踪任务出现可识别的工具失败 |
| 权限等待 | 红色 `#FF3B30` | 没有工具失败，但至少一个任务等待权限 |
| 执行中 | 黄色 `#FFD60A` | 没有异常，且至少一个任务仍在执行 |
| 全部完成 | 绿色 `#34C759` | 所有仍被跟踪的任务均已完成 |
| 空闲 | 原灯效 | 没有跟踪任务，恢复接管前配置 |

同一时间显示一个聚合状态，表格从上到下就是固定优先级。默认展示侧灯，也可选择主键区或两者。默认亮度 30%，界面提供滑条和 0–100 整数输入；四种非空闲状态可分别用取色器或 `#RRGGBB` 输入修改。颜色、区域和亮度通过 localStorage 保存，启用期间不能修改。空闲没有颜色覆盖，不写黑色。全部完成持续到新任务、会话结束、中断或失联过期改变跟踪集合，不再采用 10 秒熄灭。

UserPromptSubmit 开始新轮次并清除该会话旧任务的失败和等待；PermissionRequest 添加权限等待，PostToolUse 清除对应工具等待并检查失败。Stop 只完成主任务，仍在执行的子任务继续参与聚合；SubagentStop 删除子任务并将其失败保留到主任务。Interrupt 清空当前轮次任务，SessionEnd 删除会话，再聚合其他会话。

官方 PostToolUse 提供 `tool_response` JSON，但不保证所有工具都返回相同结构。当前只识别顶层 `isError` / `is_error` 为 true，或 `exit_code` / `exitCode` 非零。失败在本轮次保留，直到新提示、中断或会话结束；不扫描自由文本、不把 HTTP 状态码当退出码，也不持久化工具输出。因此仅在返回结构可识别时显示失败，不能宣称检测所有 shell 或工具失败。

“开启联动”由用户主动触发：空闲启动不连接 HID、不建立恢复点、不写灯；出现非空闲状态才保存所选区域的首次快照并写入。启用前需恢复所选区域的手动修改；若上次自动恢复失败，必须先重试恢复，不能切换区域覆盖旧恢复点。联动和自动恢复期间禁止手动写灯，仍可读取。每个分区写入都严格回读并验证另一分区不变，双区中任一操作失败会尝试恢复两区。

进入空闲、停止联动或正常退出时，分别恢复自动模式拥有的所选区域快照，不覆盖未接管区域。恢复点保存在内存，强制结束或键盘断连时退出不能保证恢复。模式或设备路径变更时拒绝使用旧快照，接回原设备并切回原模式后可重试。

窗口采用无边框透明配置，Windows 使用 Acrylic 毛玻璃和 Windows 11 风格按钮，macOS 使用 Sidebar 材质和红绿灯布局。页面不再保留重复的状态侧栏，灯区预览和规则设置并排展示；低透明度底色让原生材质透出。标题栏空白可拖动、双击最大化；按钮执行实际窗口命令。键盘图用于配置示意，可在开启前切换预览状态；真实灯光参数通过“读取键盘”查看，未实机验收的效果不视为已验证。

窗口配置、原生材质和后台命令不能通过前端热更新生效，必须重新编译并启动桌面后台。缺少 `get_status` 时显示明确的旧版本提示，联动不可开启，配置编辑仍可使用。

## Hook 包

按 [官方 Hook 文档](https://learn.chatgpt.com/docs/hooks)使用 `plugin/.codex-plugin/plugin.json` 和 `plugin/hooks/hooks.json`，定义 10 类同步事件。每次调用只处理 stdin JSON，stdout 返回 `{}`，失败退出码为 1，不返回会阻止 Codex 的退出码 2。Hook 进程不访问 HID、不启动界面、不读取 transcript。

这是 Windows 专用插件。命令通过 Windows PowerShell 执行插件内 `hooks/receive.ps1`，该脚本以原始字节转发 stdin，避免 JSON 被管道重新编码。每个 Hook 的超时为 3 秒。为避免不同外层 shell 展开 `$env` 或插件路径含空格导致命令损坏，启动片段使用 UTF-16LE `EncodedCommand`；全部解码内容如下：

```powershell
& (Join-Path $env:PLUGIN_ROOT 'hooks/receive.ps1')
```

进程级 `ExecutionPolicy Bypass` 只用于调用随插件提供的脚本，不修改系统执行策略，也不绕过 Codex 的 Hook 审核与信任。插件内二进制必须由当前源码构建，仓库不包含该构建产物。

准备插件时先构建 `src-tauri/src/bin/keyphore-hook.rs` 对应的 release 二进制，再执行 `plugin/package.ps1` 将产物复制到 `plugin/bin`。脚本只打包，不安装、不改配置。安装后仍需用户在 Codex 中审核并信任 Hook；加载与实际事件格式需在当前 Codex 版本验收，不使用绕过信任参数。

### 应用内一键安装

重新编译并启动桌面应用后，点击顶部“Codex 联动”打开独立弹窗，按以下顺序操作：

1. 点击“安装 Codex 联动”。后台检测原生 `codex.exe`，通过 `codex plugin list --json` 判断安装情况；已安装直接复用，不重复安装，也不修改已有信任。
2. 首次安装后，在 Codex 中审核并信任 Hook。CLI 可通过 `/hooks` 审核；尚未加载插件时需重新打开 Codex。插件被禁用时，请在 Codex 中启用后点击“重新检测”。
3. 在 Codex 中发送一条新消息。弹窗每 2 秒只读检查本地事件，收到真实事件后显示“联动已就绪”，再返回主页开启灯光联动。

新安装从应用随附资源中复制固定的插件清单、插件源清单、Hook 定义、转发脚本和接收器，放到 Tauri 当前用户应用数据目录下的 `codex-integration`，然后通过官方 CLI 登记插件源并安装插件。此目录独立于源码和应用安装位置；已有开发目录安装只复用，不自动迁移或升级。未找到原生 CLI 或 CLI 格式不兼容时明确报错，不改写 Codex 配置文件。

安装前记录验证起点，旧事件不能用于确认新安装成功；已有安装可依据最近 24 小时内的事件确认接收链路。就绪仅证明最近收到事件，不代表全部 Hook 已获信任、所有异常状态都已验收，或键盘当前已连接。安装和事件检测均不访问键盘，不自动开启灯光，也不代替用户信任 Hook。

`pnpm tauri build` 的构建前脚本 `scripts/prepare-desktop.ps1` 会先构建前端，再编译当前源码的 release 接收器，最后调用 `plugin/package.ps1` 准备插件。前端先准备是因为接收器复用的桌面库可能需要嵌入页面资源。任一步失败即停止打包；Tauri 资源配置将插件和本地插件源清单随安装包携带。本轮没有执行构建、lint 或测试，一键安装流程仍需重新编译后实机验证。只刷新前端无法添加后台安装命令。

## 存储与边界

- 只保存状态所需标识、工具名称、阶段、等待集合、失败标记和本地接收时间，不保存提示词、回复、工具参数或工具结果正文。
- `%LOCALAPPDATA%\Keyphore\status.json` 通过同目录临时文件和原子替换发布；`status.lock` 使用内核文件锁，最多等待 100 ms。
- 输入及文件上限为 1 MiB，会话、子任务和等待集合均有限制。损坏 JSON 先备份再恢复；未知文件版本、权限错误和超限文件不静默覆盖。
- 等待按工具名称关联。官方未保证审批事件有工具调用 ID，因此同名并发审批可能合并；工具事件没有子代理标识时归入主任务，不能宣称所有子代理工具都精确跟踪。
- 迟到的旧轮次工具和 Stop 不覆盖已开始的新轮次。没有官方事件时间序号，无法完全识别迟到的 UserPromptSubmit；无轮次标识的 SessionEnd 依赖正常生命周期顺序。
- 缺心跳的失联状态最多保留 24 小时。若 Hook 丢失审批结果或结束事件，等待状态可能残留；需要后续真实验收决定是否增加存活检测。
- 后台每 250 ms 聚合状态，每 2 秒健康回读或重新探测。状态未变化且参数匹配时不写灯；重连后参数丢失时仅重放当前状态。连接失败可重试，写入或已连接后的回读失败暂停联动，不盲目连续写入。
- 状态文件损坏时自动模式暂停，不将读失败当成空闲写灯。自动关闭期间不持续刷新聚合状态，下一次启动会重新读取当前状态。
