# Keyphore Windows 版设计规格

## 目标

使用 Tauri 2 构建可在 Windows 日常使用的 Keyphore，实现 Codex 任务状态到 NuPhy Air75 V3 主键区灯光的映射。

首版仅支持：

- Windows 10/11 x64。
- NuPhy Air75 V3 原厂固件。
- USB 有线连接，USB ID 为 `19f5:1028`。
- Codex Plugin 生命周期 Hooks。
- 执行中、需要操作、已完成和熄灭四种聚合状态。
- 系统托盘、状态展示、颜色与亮度设置、开机启动和本地诊断。

首版不支持蓝牙、2.4 GHz 接收器、自定义固件、多键盘并行、自动更新和云同步。

## 技术栈

- Tauri 2：桌面应用、窗口、托盘和开机启动。
- Rust：HID 通信、Codex Hook、状态聚合、配置与诊断。
- Vue 3 + TypeScript：设置界面。
- `hidapi`：访问 Windows HID 设备，不安装自定义驱动。
- JSON：保存本地设置和任务状态。

## 进程模型

### Tauri 主进程

Tauri 主进程是唯一允许访问 Air75 V3 HID 接口的进程。它负责：

- 枚举和打开键盘。
- 读取并聚合 Codex 状态。
- 仅在聚合状态改变时写入灯光。
- 写入后回读验证。
- 管理托盘、窗口、设置和开机启动。
- 在退出、断连或写入失败时尽力熄灭信号灯并释放设备。

应用采用单实例运行，避免多个进程争用 HID。

### Hook 可执行程序

`keyphore-hook.exe` 是无界面的轻量程序。每次 Hook 调用时，它从标准输入读取 JSON，过滤并转换允许的生命周期字段，然后以原子方式更新状态文件。Hook 程序不访问键盘，也不启动 Tauri 窗口。

### 本地数据

数据存储在 `%LOCALAPPDATA%\Keyphore`：

- `settings.json`：灯光、完成显示时间和启动设置。
- `status.json`：按会话和代理记录的当前状态。
- `status.lock`：Hook 与主进程之间的文件锁。
- `diagnostics.log`：有限、可轮转且不包含提示词内容的诊断日志。

## 数据流

1. Codex 生命周期事件通过 Plugin Hook 调用 `keyphore-hook.exe`。
2. Hook 程序校验输入大小和事件类型，只保留状态计算所需字段。
3. Hook 程序获取有界文件锁并原子更新 `status.json`。
4. Tauri 主进程检测状态文件变化并执行状态聚合。
5. 聚合优先级为：需要操作、执行中、已完成、熄灭。
6. 只有可见聚合状态改变时才向 Air75 V3 写入灯光。
7. HID 层回读主键区状态，并验证侧边灯状态未改变。

## Air75 V3 HID 边界

设备必须匹配以下条件：

- Vendor ID：`0x19f5`。
- Product ID：`0x1028`。
- 产品名：`Air75 V3` 或 `NuPhy Air75 V3`。
- USB 有线总线。
- 控制接口预期为 Interface 3、Usage Page `0x0001`、Usage `0x0000`。

Windows 枚举可能与 macOS 存在差异，因此实现分成两层：

- 严格身份匹配：VID、PID、产品名和 USB 总线不可放宽。
- 控制接口解析：优先匹配已知接口属性；若 Windows 未暴露相同接口编号，只读探测会报告所有候选接口，不会自动尝试写入。

协议沿用现有 Keyphore 的 64 字节 NuPhy 报文、临时会话握手、校验和及响应关联。Air75 V3 写入主状态后不执行 Air65 V3 的额外亮度镜像写入，避免颜色被二次缩放。

实际灯光测试必须由用户主动触发，顺序为蓝、橙、绿、熄灭。每一步写入后必须回读匹配，并确保受保护的侧边灯字节不变。

## 界面

界面包含四个区域：

1. 状态：显示 Codex 聚合状态、键盘连接状态和协议健康状态。
2. 灯光：设置执行中、需要操作和已完成的颜色、亮度及可见性。
3. 测试：执行只读探测，以及经用户确认的实体灯光测试。
4. 设置：管理完成提示持续时间、开机启动、Hook 安装或移除及诊断信息。

关闭窗口只隐藏到托盘；明确选择退出时才停止应用并尝试熄灯。

## 异常处理

- 未连接键盘：应用保持运行并低频重新探测。
- 多个匹配设备或接口：拒绝写入并显示诊断信息。
- HID 写入或回读失败：停止后续颜色写入，尝试熄灯并释放设备。
- USB 断连、休眠或唤醒：重新枚举设备，连接恢复后重放当前聚合状态。
- 状态文件损坏：将原文件重命名为带时间戳的备份并恢复为空状态。
- Hook 获取锁超时：快速失败，避免阻塞 Codex。
- 配置值越界：拒绝保存并继续使用最后一个有效配置。

## 安全与隐私

- 不请求管理员权限，不安装驱动或 Windows Service。
- Hook 不保存提示词、对话正文、工具输入或工具输出。
- 所有数据保存在本机用户目录，不上传遥测或诊断。
- 首次灯光写入必须由用户主动触发测试。
- UI 前端不能直接访问文件系统或 HID，只能调用明确暴露的 Tauri Command。

## 验证策略

验证按以下顺序执行：

1. Rust 协议编码、解码、校验和及状态聚合单元测试。
2. Windows 只读设备枚举和候选接口输出。
3. Air75 V3 临时会话握手及 17 字节灯光状态只读检查。
4. 用户确认后的实体灯光测试及侧边灯保护验证。
5. Codex Hook 生命周期状态流测试。
6. USB 重连、单实例、托盘退出和配置持久化验证。
7. Windows 安装包安装与卸载验证。

只读探测失败时停止硬件实现并保留诊断结果，不通过猜测接口或批量写入寻找控制端点。

## 交付与版本管理

- 工作区：`E:\Keyphore-Windows`。
- GitHub 仓库：完成核心实现和本地验证后创建为私有仓库。
- 仓库不得提交本地配置、诊断日志、构建产物、用户路径或签名凭据。
- 首个可用版本完成 Air75 V3、Codex Hooks、托盘、设置、开机启动和诊断。
- 自动更新、多语言和无线连接留到后续版本。

## 完成标准

满足以下条件时首版完成：

- Windows 能稳定识别并打开一把有线 Air75 V3。
- 只读握手和状态读取成功。
- 实体键盘正确显示三种任务颜色并最终熄灭主键区信号灯。
- 侧边灯在所有写入前后保持不变。
- Codex 的执行、等待输入和完成事件能正确驱动键盘状态。
- 应用可从托盘运行、保存设置、随用户登录启动并安全退出。
- 安装包可在当前 Windows 环境完成安装和卸载。
